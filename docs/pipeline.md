# Как работает распознавание

Один запрос → один документ. Тип студент выбирает вручную.

```text
main.py
  → recognition_service.py
      → document_loader.py: проверка файла, PDF в PNG
      → ocr_service.read_ocr_blocks: один вызов EasyOCR
      → blocks_to_text: собрать фрагменты одной строки
      → document_fields.py: выбрать схему и извлечь поля
      → marks_service.py: проверить графические отметки
  → JSON с текстом, координатами и карточкой
```

## Где менять код

- **main.py** — только приём запроса, ограничения, рабочий поток и ответ.
- **document_loader.py** — JPEG/PNG и одностраничный PDF. Сначала проверяется
  размер будущего изображения, затем рендерится страница. Встроенный текст PDF
  не подставляется вместо OCR.
- **field_extractor.py** — сохранён твой обработчик справки об обучении.
  Исправлены регистр/пробелы дат и точное написание «не найдено».
- **document_fields.py** — схемы заявления на отпуск и справки о практике.
  Слева ключ из README, справа допустимые метки на документе.
- **marks_service.py** — простые проверки пикселей около меток. Круг возле
  «М.П.» считается кандидатом на печать; связные штрихи возле подписи — на подпись.
  Печатная метка и пустая горизонтальная линия сами по себе не достаточны.
- **recognition_service.py** — соединяет эти шаги. Вся обработка выполняется
  в одном рабочем потоке под существующим ограничителем; OCR вызывается один раз.

## Что проверено тестами

Тесты находятся в `tests/`. Они создают PDF и картинки сами, без персональных
данных и без скачивания весов. Проверяют API, ограничения, повреждённые файлы,
PDF с паролем/несколькими страницами, поля трёх типов, оба формата дат,
пропуски, разделение метки/значения на OCR-блоки и наличие/отсутствие макетов отметок.
`tests/check_fields.py` можно запустить отдельно из корня проекта:
`PYTHONPATH=. python tests/check_fields.py` (Linux/macOS).

## Границы этой версии

Это распознавание и карточка, **не весь кейс**. Вопрос ещё не обрабатывается;
проверка комплектности, ответы с источниками и экспорт results.json — следующий этап.
Схемы остальных двух типов нужно дополнительно прогнать на документах организаторов.

Графические проверки — эвристики для учебного оформления, не универсальная модель.
Если метка не прочитана или макет отличается, отметка может не обнаружиться.
Нужны полный стартовый набор и проверка пропусков. Не делаем выводов по идентификатору
open-001 и не подставляем эталонные карточки вместо обработки картинки.

## Проверка на доступном документе

Через настоящий EasyOCR на CPU и /analyze обработана присланная справка open-001:
PDF и PNG вернули одинаковые поля; графические подпись и печать обнаружены.
В копии изображения с удалёнными штрихами подписи и круговыми контурами печати
(печатные метки оставлены) оба флага стали false. Это диагностическая копия,
не документ из официального набора с пропусками.

Осталась ошибка OCR в названии вуза: «кМеридианх» вместо кавычек вокруг «Меридиан».
Она не исправляется подстановкой известного названия. Проверка всего стартового
набора не выполнена: доступен только один исходный пример.
