# Online Dekanat Backend

Небольшой FastAPI-сервис для распознавания русского и английского текста на фотографиях.
Сейчас он выполняет только OCR: вопрос проверяется и возвращается в ответе,
но не используется для поиска документов или генерации ответа.

## Запуск

Используйте Python 3.11–3.13. Команды ниже выполняются из корня проекта.

```bash
python -m venv .venv
```

Активируйте окружение:

```bash
# Linux / macOS
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Для запуска на CPU сначала установите CPU-сборки PyTorch, чтобы не скачивать
ненужные библиотеки CUDA, затем остальные зависимости:

```bash
python -m pip install --upgrade pip
python -m pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -m pip check
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

При первом запуске EasyOCR может скачивать модели. Нужны доступ в интернет,
место на диске и права записи в каталог моделей EasyOCR (`~/.EasyOCR` по умолчанию).
Следующие запуски используют скачанные модели. Не запускайте несколько процессов
(`--workers`) без расчёта памяти: каждый загрузит отдельный экземпляр модели.
`--reload` можно использовать при разработке, но перезапуск загружает модель заново.

### GPU

По умолчанию `OCR_GPU=false`. Допустимы `true`, `false`, `1`, `0` без учёта регистра.
Для NVIDIA GPU установите совместимые с драйвером CUDA-сборки PyTorch и torchvision
по инструкции https://pytorch.org/get-started/locally/ вместо CPU-команды выше.
Одна переменная окружения не устанавливает драйверы и не гарантирует доступность GPU.

```bash
OCR_GPU=true python -m uvicorn main:app
```

```powershell
$env:OCR_GPU = "true"
python -m uvicorn main:app
```

## API

Интерактивная документация: http://127.0.0.1:8000/docs.

### `GET /health`

```json
{"status": "ok"}
```

Сервер начинает принимать запросы после успешной инициализации модели.
Этот endpoint проверяет доступность процесса, а не качество распознавания.

### `POST /analyze`

Формат запроса — `multipart/form-data`:

- `prompt`: непустой после удаления пробелов по краям вопрос, максимум 2000 символов до удаления пробелов;
- `photos`: от 1 до 4 файлов JPEG или PNG;
- каждый файл — максимум 10 МиБ (10 × 1024 × 1024 байт);
- каждое изображение — максимум 20 000 000 пикселей;
- всё тело запроса — максимум 42 МиБ, включая multipart-разметку.

```bash
curl http://127.0.0.1:8000/analyze \
  -F 'prompt=Какой текст на документе?' \
  -F 'photos=@document.png;type=image/png'
```

Для нескольких фотографий повторите `-F 'photos=@...;type=...'`.

```json
{
  "status": "received",
  "promt": "Какой текст на документе?",
  "photos": 1,
  "answers": ["Распознанный текст"]
}
```

Ключ `promt` сохранён для совместимости с прежним API. Входное поле называется
`prompt`. `answers` содержит OCR-текст в порядке фотографий, а не ответы на вопрос.
Если текст не найден, соответствующая строка пустая. Ошибка одной фотографии
прерывает весь запрос; частичный успешный результат не возвращается.

Ошибки содержат поле `detail`:

- `400` — некорректный запрос, например повреждённая multipart-разметка;
- `413` — превышен лимит байтов файла или тела запроса;
- `422` — ошибка параметров, формата, декодирования или разрешения изображения;
- `503` — сбой OCR; внутренние подробности клиенту не возвращаются.

Фотографии не сохраняются приложением в постоянное хранилище. Starlette может
использовать временные файлы при разборе загрузки; после обработки они закрываются.
Логи приложения не содержат вопрос, OCR-текст и содержимое файлов; для сбоя OCR
записывается только тип исключения.

## Проверки

Тесты используют подмену OCR, поэтому не требуют GPU, EasyOCR, PyTorch или моделей.
Их можно запускать в отдельном окружении, установив только тестовые зависимости:

```bash
python -m pip install -r requirements-test.txt
python -m pytest
ruff check .
ruff format --check .
```

GitHub Actions запускает эти проверки на Python 3.11 и 3.13 для push и pull request.
Автоматические тесты проверяют API и обработку изображений, но не точность EasyOCR.
Прямые зависимости закреплены; полный lock-файл транзитивных зависимостей не ведётся.

## Ограничения эксплуатации

Распознавания выполняются в рабочем потоке, по одному на процесс, чтобы не блокировать
цикл событий и не вызывать модель одновременно. Другие запросы OCR ждут своей очереди.
Жёсткого таймаута и ограничения длины этой очереди нет. Поток не ускоряет само OCR.

Это не готовый публичный сервис: нет авторизации и ограничения частоты запросов.
Для публичного размещения нужны контроль доступа, лимиты соединений/частоты запросов
и размера тела на reverse proxy, HTTPS и правила обработки персональных данных.
При больших нагрузках очередь и отдельные процессы OCR следует проектировать отдельно.
