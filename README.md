# Online Dekanat Backend

Один JPEG, PNG или одностраничный PDF → локальный Tesseract OCR → карточка
полей. Тип выбирается вручную: справка об обучении, заявление на академический
отпуск или справка о практике. Вопрос пока только проверяется на непустоту:
проверка комплектности, ответы по Положению и экспорт `results.json` ещё не реализованы.

## Установка и запуск

Запускайте команды **из корня проекта**, где находятся `main.py` и `models/`.

```bash
python -m venv .venv
```

Активация на Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

На Linux/macOS: `source .venv/bin/activate`.

### Windows: Python 3.14, 64-bit

Для этой версии Python использована готовая сборка `tesserocr`, включающая
нативные библиотеки Tesseract. Отдельный установщик Tesseract не нужен.
Если эта сборка уже установлена в `.venv`, повторно скачивать её не нужно.

```powershell
python -m pip install https://github.com/simonflueckiger/tesserocr-windows_build/releases/download/tesserocr-v2.11.0-tesseract-5.5.3/tesserocr-2.11.0-cp314-cp314-win_amd64.whl
python -m pip install -r requirements.txt
```

Этот wheel подходит только для CPython 3.14 / Windows x64. Для другой версии
Python нужна соответствующая готовая сборка из релизов tesserocr-windows_build;
не устанавливайте cp314-wheel в Python 3.11–3.13. Обычная установка из PyPI
на Windows может перейти к сборке из исходников и потребовать нативные библиотеки.

### Linux: Python 3.11–3.13

Если готового wheel нет, `tesserocr` собирается с системными библиотеками.
Для Debian/Ubuntu сначала установите зависимости сборки:

```bash
sudo apt-get update
sudo apt-get install -y build-essential python3-dev pkg-config libtesseract-dev libleptonica-dev
python -m pip install -r requirements.txt
```

Для других систем используйте соответствующие пакеты Tesseract/Leptonica.
Нативная установка отличается по платформам; полная чистая установка на каждой
платформе отдельно не проверена.

### Модель и сервер

Русская модель уже находится в репозитории: `models/tessdata/rus.traineddata`.
Источник: `tesseract-ocr/tessdata_fast`, версия 4.1.0. Модель используется локально;
приложение не скачивает её при запросе. EasyOCR и PyTorch больше не используются.

```bash
python -m pip check
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Открыть форму для технической проверки: http://127.0.0.1:8000/docs.
Краткая схема кода: [docs/pipeline.md](docs/pipeline.md).

## API

`GET /health` возвращает `{"status": "ok"}`. Это проверка доступности процесса,
а не готовности OCR: движок создаётся при обработке документа.

`POST /analyze`, `multipart/form-data`:

- `photos`: ровно один JPEG, PNG или одностраничный PDF;
- `prompt`: непустой вопрос, максимум 2000 символов;
- `document_type`: `study_certificate`, `academic_leave_application`
  или `internship_certificate`;
- максимум 10 МиБ на файл и 20 мегапикселей на изображение/рендер PDF;
- PDF с паролем не поддерживается.

Текущий ответ содержит **только** `document_type` и `fields`.
OCR-текст вычисляется внутри, но пока не возвращается. Даты — `YYYY-MM-DD`,
курс — строка с целым числом, текстовый пропуск — `"не найдено"`, отметки — boolean.
Для академического отпуска поля печати нет. Это карточка, а не решение о принятии.

Ошибки: `422` — параметры/некорректный файл, `413` — файл больше лимита,
`503` — ошибка OCR без внутренних подробностей в ответе.

## Тесты

Unit-тесты заменяют нативный модуль Tesseract и OCR: не требуют его установки,
весов, EasyOCR, PyTorch или GPU. Проверяют API, загрузчик, поля, даты, графические
эвристики и контракт OCR на подменённом движке. Они не измеряют качество OCR.

```bash
python -m pip install -r requirements-test.txt
python -m pytest
ruff check .
ruff format --check .
```

GitHub Actions выполняет эти проверки на Python 3.11 и 3.13.
Настоящий OCR отдельно проверялся через API на 17 присланных PDF
(open-001…open-015, open-029, open-030) и PNG/JPEG из этих PDF:
все поля совпали с учебным эталоном. Это не проверка всего набора из 30 документов
и не гарантия качества на произвольных реальных документах.

## Инструменты и ограничения

Tesseract через `tesserocr` + русская модель `tessdata_fast`; PyMuPDF рендерит PDF;
Pillow читает изображения; OpenCV/NumPy проверяют штрихи подписи и круглую печать.
Поля извлекаются регулярными выражениями. Внешние OCR/LLM API не используются.

Проверяется наличие отметок, не подлинность. Эвристики рассчитаны на учебные макеты.
OCR вызывается один раз на документ; текст и координаты берутся из одного результата.
Тяжёлая обработка вынесена в рабочие потоки. Отдельного ограничителя OCR-очереди,
общего лимита тела до multipart-разбора, таймаута, авторизации и rate limiting нет.
Для публичного размещения эти ограничения нужно обеспечить отдельно.
Файлы закрываются после обработки и не сохраняются приложением постоянно.
