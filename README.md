# Online Dekanat Backend

FastAPI-сервис: один JPEG, PNG или одностраничный PDF → локальный OCR → карточка
полей выбранного типа документа. Поддерживаются справка об обучении, заявление
на академический отпуск и справка о практике.

Вопрос пока только проверяется: ответы по Положению и итоговый `results.json`
ещё не реализованы. Как устроен код: [короткое объяснение](docs/pipeline.md).

## Запуск

Используйте Python 3.11–3.13. Команды ниже выполняются из корня проекта.

```bash
python -m venv .venv
```

Активируйте окружение:

```bash
# Linux / macOS
source .venv/bin/activate
```

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Для запуска на CPU сначала установите CPU-сборки PyTorch, чтобы не скачивать
ненужные библиотеки CUDA, затем остальные зависимости:

```bash
python -m pip install --upgrade pip
python -m pip install torch==2.14.1 torchvision==0.29.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
python -m pip check
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

При первом запуске EasyOCR может скачивать модели. Нужны доступ в интернет,
место на диске и права записи в каталог моделей EasyOCR (`~/.EasyOCR` по умолчанию).
При первом анализе также скачиваются русские веса Tesseract (~4 МБ) в
`~/.cache/online-dekanat/tessdata`; контрольная сумма проверяется. Для офлайн-запуска
скачайте их заранее: `python -m services.text_ocr_service`.
Следующие запуски используют скачанные модели. Не запускайте несколько процессов
(`--workers`) без расчёта памяти: каждый загрузит отдельный экземпляр модели.
`--reload` можно использовать при разработке, но перезапуск загружает модель заново.

### GPU

По умолчанию `OCR_GPU=false`. Допустимы `true`, `false`, `1`, `0` без учёта регистра.
OCR_GPU управляет EasyOCR; текстовый Tesseract работает на CPU.
Для NVIDIA GPU установите совместимые с драйвером CUDA-сборки PyTorch и torchvision
по инструкции https://pytorch.org/get-started/locally/ вместо CPU-команды выше.
Одна переменная окружения не устанавливает драйверы и не гарантирует доступность GPU.

```bash
OCR_GPU=true python -m uvicorn main:app
```

```powershell
$env:OCR_GPU = "true"
python -m uvicorn main:app
```

## API

Интерактивная документация: http://127.0.0.1:8000/docs.

### `GET /health`

```json
{"status": "ok"}
```

Сервер начинает принимать запросы после успешной инициализации модели.
Этот endpoint проверяет доступность процесса, а не качество распознавания.

### `POST /analyze`

Формат запроса — `multipart/form-data`:

- `prompt`: непустой вопрос, максимум 2000 символов;
- `document_type`: `study_certificate`, `academic_leave_application`
  или `internship_certificate`;
- `photos`: ровно один JPEG, PNG или одностраничный PDF;
- файл — максимум 10 МиБ; изображение / отрендеренная страница — 20 мегапикселей;
- всё тело запроса — максимум 42 МиБ. PDF с паролем не поддерживается.

```bash
curl http://127.0.0.1:8000/analyze \
  -F 'prompt=Какая дата выдачи?' \
  -F 'document_type=study_certificate' \
  -F 'photos=@document.pdf;type=application/pdf'
```

Ответ содержит:

- `status: "received"` — обработка завершилась, это **не** принятие документа;
- `document_type` — выбранный тип;
- `ocr_text` — распознанный текст;
- `fields` — все ключи выбранного типа из стартового README.

Текстовые пропуски: `"не найдено"`; даты: `YYYY-MM-DD`; курс: строка с целым
числом; подпись и печать: boolean. У заявления на отпуск поля печати нет.
Координаты EasyOCR используются внутри обработки и не возвращаются в API.

Подпись и печать проверяются по пикселям, не по словам «Подпись»/«М.П.».
Это простые эвристики: связные штрихи справа от метки подписи и круглый контур
над «М.П.». Они требуют читаемых меток и похожего оформления, не проверяют
подлинность и **не гарантируют** точность на всех вариантах стартового набора.
OCR-ошибки в ФИО, названиях и номерах не заменяются догадками.

Ошибки содержат поле `detail`:

- `400` — некорректный запрос, например повреждённая multipart-разметка;
- `413` — превышен лимит байтов файла или тела запроса;
- `422` — ошибка параметров, формата, декодирования или разрешения изображения;
- `503` — сбой OCR; внутренние подробности клиенту не возвращаются.

Фотографии не сохраняются приложением в постоянное хранилище. Starlette может
использовать временные файлы при разборе загрузки; после обработки они закрываются.
Логи приложения не содержат вопрос, OCR-текст и содержимое файлов; для сбоя OCR
записывается только тип исключения.

## Проверки

Тесты используют подмену OCR, поэтому не требуют GPU, EasyOCR, PyTorch или моделей.
Их можно запускать в отдельном окружении, установив только тестовые зависимости:

```bash
python -m pip install -r requirements-test.txt
python -m pytest
ruff check .
ruff format --check .
```

GitHub Actions запускает эти проверки на Python 3.11 и 3.13 для push и pull request.
Автоматические тесты проверяют API, PDF, три схемы полей, даты, пропуски,
разделённые OCR-строки и графические отметки на нарисованных примерах. Они не
доказывают точность EasyOCR или качество на полном наборе организаторов.
Прямые зависимости закреплены; полный lock-файл транзитивных зависимостей не ведётся.

## Ограничения эксплуатации

Распознавания выполняются в рабочем потоке, по одному на процесс, чтобы не блокировать
цикл событий и не вызывать модель одновременно. Другие запросы OCR ждут своей очереди.
Жёсткого таймаута и ограничения длины этой очереди нет. Поток не ускоряет само OCR.

Это не готовый публичный сервис: нет авторизации и ограничения частоты запросов.
Для публичного размещения нужны контроль доступа, лимиты соединений/частоты запросов
и размера тела на reverse proxy, HTTPS и правила обработки персональных данных.
При больших нагрузках очередь и отдельные процессы OCR следует проектировать отдельно.

## Локальные инструменты

Tesseract через tesserocr 2.11.0: локальное чтение текста, русские веса
`tessdata_fast/4.1.0/rus.traineddata` (алфавит включает кавычки «»).
EasyOCR 1.7.2: координаты меток для графических отметок, модели CRAFT и кириллицы
(выбор по умолчанию Reader для `ru`, `en`); PyTorch / torchvision — CPU-инференс;
PyMuPDF — рендер PDF; Pillow — чтение изображений; OpenCV / NumPy — поиск
графических отметок. Извлечение полей — регулярные выражения и обычный Python.
Внешние OCR/LLM API не используются. Веса загружаются при первом запуске;
для офлайн-запуска их нужно скачать заранее.

Для tesserocr предпочтительна готовая wheel-сборка. Если для вашей платформы
pip пытается собрать библиотеку из исходников, потребуются системные библиотеки
Tesseract и Leptonica; это описано в инструкции tesserocr. Проверка выполнена
на Linux x86_64 / Python 3.13 с готовой wheel-сборкой.
